# 🐑 dsh-shepherd

> 让你的 Agent 保持理智、高效与可控的全面行为守卫插件。

在现代 AI 工作流中，Agent 经常会陷入无意义的死循环、反复读取同一个文件、或者在没有执行任何验证的情况下“谎称”任务已完成。**dsh-shepherd** 专为 DSH 打造，它是一套结合了**循环守护**与**模式守卫**的终极防御系统。

## ✨ 核心优势

- **全方位异常捕捉**：内置 7 大专属检测器，无论是文本复读、工具参数的周期性重试，还是结果的振荡与假完成，统统无法逃脱。
- **精细的分级干预**：告别粗暴的“一刀切”中断。系统内置仲裁层，会根据异常严重程度，智能选择警告、阻断单次工具调用、或强制终止本轮生成。
- **智能进度感知**：自动剥离时间戳、UUID 等无用变量，计算真正的状态指纹。合法的轮询绝不误杀，真实的死锁绝不放过。
- **灵活的工作流状态**：支持规划、编码、验证三种模式的动态切换，在限制危险操作的同时，保留极高的执行自由度。
- **可视化审计控制台**：内置前端悬浮窗，支持一键拖拽、动态配置参数，并实时拉取最近的工具拦截记录。

## 🛡️ 7 大循环检测器

插件实时监听 Agent 的思考流与工具调用流，确保行为始终在正轨：

- **A. 文本重复**：当模型输出大量完全相同的文本块或字符周期时触发。
- **B. 工具重复**：当模型反复调用同一个工具，且忽略了分页或重试参数构成周期时触发。
- **C. 无进展**：连续多次工具调用的结果毫无变化，或结果在几个固定值之间来回振荡时触发。
- **D. 工具超时**：单次工具调用执行时间过长，超过预设阈值未返回时触发。
- **E. 无落地**：连续多轮生成既没有输出可见文本，也没有调用任何工具，处于纯思考空转时触发。
- **F. 硬上限**：单轮交互的步数或总耗时达到了强行设置的安全上限时触发。
- **G. 无证据完成**：模型宣称任务完成或已修复，但本回合内没有任何成功的工具调用作为证据，或写操作后未进行验证时触发。

## 🚦 3 态模式守卫

你可以随时在悬浮窗中切换当前工作模式，严格管控高风险工具的执行：

- **📋 planning（规划模式）**：只读分析阶段，允许阅读和思考，但禁用任何修改文件或执行命令的工具。
- **⌨️ coding（编码模式）**：允许编写代码，但当模型尝试调用黑名单中的敏感工具（如终端命令、测试运行器）时，会触发人工审批或熔断机制。
- **🚀 verify（验证模式）**：测试与验证阶段，放行执行类工具，确保代码的真实可用性。

## ⚙️ 配置示例

你可以通过 DSH 的插件配置文件自定义所有阈值。以下是一个典型的配置结构：

```json
{
  "loop": {
    "enabled": true,
    "maxInterruptsPerAgent": 3,
    "noEvidence": { "keywords": ["完成", "done"] }
  },
  "mode": {
    "enabled": true,
    "mode": "planning",
    "blacklist": ["execute_command", "pytest"]
  }
}
```

**关键参数说明**：

- `maxInterruptsPerAgent`：同一个 Agent 被强行打断的最大次数，防止无限打断套娃。
- `noProgress.window`：连续多少次无进展结果触发报警。
- `mode.blacklist`：在编码模式下，哪些工具需要用户手动审批。

## 🧠 工作原理简述

1. **状态采集**：监听 Agent 的流式文本与工具执行事件。
2. **指纹剥离**：对工具结果剥离时间戳、耗时等易变量后再计算哈希。
3. **仲裁决策**：根据检测器的置信度与历史触发次数，决定干预级别。
4. **分发干预**：
   - 警告：注入系统提示，不打断模型。
   - 阻断：在工具执行前返回拒绝，拦截单次调用。
   - 终止：强制取消本轮生成，并注入强指令。
